# Алгоритм и защита

## Последовательность работы
1. `create-source` создаёт настольную SQLite БД `data/source_bookstore.db` с одной ненормализованной таблицей `sales_flat`.
2. `init-schema` применяет `sql/001_schema.sql` к PostgreSQL и создаёт нормализованные таблицы.
3. `import` читает каждую строку SQLite, получает или создаёт справочники покупателя, сотрудника, жанра и автора, затем создаёт книгу, связь книга–автор и факт продажи.
4. Команда не меняет значения предметной области: она только распределяет их по таблицам. Уникальный `sale_number` не допускает дублей при повторном импорте.
5. `export` выполняет агрегирующий SQL-запрос по `sold_at`, записывает набор отчёта в CSV и запускает `scripts/render_report.py`.
6. Внешний Python-скрипт считывает CSV, помещает значения в лист Excel, оформляет заголовки, ширины столбцов, денежный формат и сохраняет `reports/sales_by_day.xlsx`.

## Что показать преподавателю
- Файл `data/source_bookstore.db`, таблицу `sales_flat` и её повторяющиеся сведения.
- `sql/001_schema.sql` как воспроизводимый скрипт схемы PostgreSQL.
- Таблицы PostgreSQL и связи `genres` → `books` (1:M), `books` ↔ `authors` (M:M).
- Команду импорта и результат `SELECT * FROM sales`.
- Повторный запуск импорта: число продаж не увеличится.
- Сформированный `reports/sales_by_day.xlsx`.

## Краткий ответ на защите
«Я взял предметную область книжного магазина. Исходные данные лежат в SQLite в одной ненормализованной таблице. Скрипт PostgreSQL создаёт семь таблиц со справочниками и связями. Приложение читает источник, сохраняет значения без изменения и распределяет их по нормализованной структуре. Затем приложение получает агрегированную выборку продаж по дням, передаёт её отдельному Python-скрипту и получает Excel-отчёт».
